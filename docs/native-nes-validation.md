# 原生 NES 真机验证

本次新增独立的原生播放器，使用小程序 Canvas（优先 WebGL，自动回退 2D）、JSNES 2.1.0 和 `wx.createWebAudioContext`。现有 H5 播放器、后台部署和联机入口继续保留。

开发前基线：提交 `8299847`，带注释标签 `pre-native-nes-20260920`。

## 打开方式

1. 首次拉取时执行 `pnpm install --frozen-lockfile`，然后执行 `pnpm wechat:build`。
2. 微信开发者工具打开工程，重新编译。
3. 首页点击 **原生 NES 验证 ↗**，默认加载《赤色要塞》。卡带详情页也有同名入口。
4. 点击 **开始验证**，等待标题画面后按屏幕上的 **START** 开始游戏。
5. 使用开发者工具的预览 / 真机调试，由 iPhone 微信打开同一入口。

也可以建立自定义编译条件：启动页面 `pages/native-nes/index`，启动参数 `id=nes-chise-yaosai`。

页面入口：`miniprogram/pages/native-nes/index.ts`。当前使用 `miniprogram/config.ts` 中的线上服务地址，无需重新部署服务器。

## 网络和文件

- 小程序后台 **服务器域名 → request 合法域名** 配置 `https://minigames.19ba.cn`。
- 游戏信息及 ROM 均通过 `wx.request` 获取；ROM 使用 ArrayBuffer，此页不需要 downloadFile、socket 或 web-view 业务域名。
- 模拟器随小程序代码包发布，不远程下载或执行 JS；`pnpm wechat:build` 自动生成核心，无需手动“构建 npm”。
- ROM 下载后核对大小、文件头及 SHA-256。商业 ROM 不写入仓库或小程序代码包。
- 核心构建：`jsnes-2.1.0-perf1`（包含 `sprites1` 图块修复）；存档格式仍为 `jsnes-2.1.0-native-v1`，原生快存可以继续读取；目标 60 个模拟帧/秒，44100 Hz 音频采样率。
- 原始《赤色要塞》的 `DiskDude!` 头部由核心识别，源文件未修改。SHA-256：`98ed6d10391cccef249ce45cd935eb6263163f727fbf2fc11adb8116aa49f31d`。

## 已实现范围

- 原生 256×240 画面，按比例适配横竖屏；无 web-view。
- 固定八方向摇杆，中心死区和方向边界防抖；A/B 斜排，可与方向同时按住。
- START、SELECT、暂停 / 继续、声音开关、重开确认。
- 离开页面、切后台或旋转屏幕时暂停并释放按键；返回后手动继续。
- 1 个本地快存，可退出页面后读取；按 ROM SHA 和核心版本隔离，先写临时文件再替换。
- 显示实际模拟帧率；菜单可复制设备、微信版本、ROM、运行帧数、音频断供次数和错误信息。

本阶段只验证单人 NES。原生页不接联机，不导入网页 FCEUmm 存档，也不承诺其他 ROM / PAL / NES 2.0 / 三手柄兼容性。已根据 iPhone 16 Pro 约 35 FPS 的反馈进行第一轮计算与绘制优化；持续游玩的发热表现仍需真机测量。

## 汽车图块修复（2026-09-20）

原始 JSNES 2.1.0 在 `renderSpritesPartially` 中处理 8×16 精灵时，已清除图块编号最低位，却在选择 `$1000` 图案表时又减去 1，导致取到相邻图块。《赤色要塞》的汽车和直升机都受影响。此异常可以直接在核心输出中复现，与微信 Canvas 缩放无关。

`scripts/jsnes-sprite-patch.mjs` 在打包阶段修正该索引，同时修正两处精灵零号命中判断对垂直翻转重复交换上下半块的问题，使画面和命中判断使用一致的行。安装目录中的上游文件和 ROM 均不改写；上游 PPU 源码不匹配时构建会失败，不能静默套用补丁。

回归测试 `tests/native-sprites.test.ts` 使用自制图案，覆盖两个图案表、8×8/8×16 模式、四种翻转、背景优先级、透明像素和零号精灵命中。两项测试在原核心失败，应用补丁后通过。原始《赤色要塞》按相同按键及帧数运行，对比修复前后输出，汽车和直升机均恢复完整；旧核心状态经新核心恢复后可以继续绘制。

## iPhone 卡顿优化（perf1）

用户反馈：iPhone 16 Pro 功能正常，约 35 个模拟帧/秒。桌面性能采样定位到逐像素颜色转换，以及 PRG 银行切换时逐字节复制的开销；真机中原生绘制桥接的占比尚待分项数据确认。

- 优先通过 WebGL 上传模拟器帧缓冲的字节视图，由着色器补齐不透明度，省去每帧 61,440 个像素的逐通道转换。纹理、顶点和着色器复用；不支持 WebGL 时创建独立的 2D Canvas 回退，2D 也使用打包像素写入。
- 一次回调内需要追赶多个模拟帧时，只提交最后一帧。模拟仍按 60 Hz 推进，不降低游戏速度或音频采样率；提前预约下一次回调以减少调度空档。
- `scripts/jsnes-memory-patch.mjs` 对独立且范围有效的 Uint8Array 使用原生批量复制；对象图块列表、重叠视图等保留原来的逐项复制，CPU / PPU / APU 时序未改。
- 摇杆和按钮的外观反馈最多约 30 次/秒合并 `setData`；输入到模拟器仍然即时，暂停或离开时立即释放。新增分项指标随“复制真机测试信息”一起导出。

验证结果：三套 TypeScript 检查及小程序编译通过；32 项单元测试中 31 项通过、1 项历史用例跳过。独立 WebGL 浏览器测试逐像素核对 2D / GPU 输出、透明度、上下方向及绘制表面重建，全部一致。

可运行 `node --jitless scripts/benchmark-native.mjs` 重现桌面压力测试（用 `NATIVE_ROM_PATH` 指定本机 ROM）。本机 macOS arm64 / Node 20.11.0，600 个测量帧的平均“模拟 + 像素准备”耗时由 **26.06 ms 降至 20.40 ms（约 21.7%）**；完整画面序列、音频采样和最终序列化状态摘要一致。该测试不包含微信的原生绘制 / 音频调度 / setData，不是 iPhone FPS 或发热测量。结果写入忽略目录 `.local/native-benchmark/result.json`，不上传 ROM 或运行状态。

perf1 的微信开发者工具画面复核在 Mac 锁屏时受阻；GPU 的实际小程序显示、真机帧率与音频听感仍需复测。菜单中的“模拟含音频”是每模拟帧的 JS 平均用时，“绘制提交”是提交调用的 JS 平均用时，不代表 GPU 完成时间；绘制提交 FPS 也不等于实测屏幕刷新率。

开发者工具修改代码后应点击“编译”完整重启测试。Canvas / 核心运行实例不依赖热重载恢复。

原生实现解决业务域名依赖；公开发布的主体、服务类目、备案与游戏内容资格仍需单独核实。
